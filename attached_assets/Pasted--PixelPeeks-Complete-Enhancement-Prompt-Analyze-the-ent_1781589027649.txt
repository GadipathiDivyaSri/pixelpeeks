# PixelPeeks Complete Enhancement Prompt

Analyze the entire PixelPeeks codebase and improve the application without removing existing features.

## Main Goal

Make PixelPeeks a professional cybersecurity-grade steganography platform with strong decoding, secure encryption, OTP authentication, steganalysis, and polished UI.

## 1. Decode Module — Highest Priority

* Improve the Decode page UI and workflow.
* Make decoding faster and more reliable.
* Detect hidden data automatically where possible.
* Show clear success and error messages.
* Support password-protected decoding.
* Add copy extracted text button.
* Add download extracted message option.
* Show file metadata and decoding result details.
* Handle corrupted, unsupported, or empty files properly.

## 2. Cross-App Decoding Compatibility

* Improve support for images encoded by other steganography apps.
* Detect common LSB-based image steganography.
* Support PNG and BMP decoding techniques.
* Add compatibility checker.
* Show clear message if the file uses unsupported encoding.
* Explain that JPEG decoding may fail because compression can destroy hidden data.

## 3. Encryption & Security

Use modern encryption.

Default:

* AES-256-GCM

Password-Based Key Derivation:

* Argon2 preferred
* PBKDF2 fallback

Requirements:

* Never use raw password directly as encryption key.
* Generate secure random salt.
* Generate secure random IV.
* Store only salt, IV, authentication tag, and encrypted payload.
* Encrypt hidden message before embedding.
* Detect wrong password properly.
* Show clear decryption errors.
* Keep backward compatibility with existing PixelPeeks encoded files if possible.

Optional future encryption methods:

* AES-256-CBC
* ChaCha20-Poly1305
* Triple DES only for educational/legacy support

## 4. OTP & Two-Factor Authentication

Do not use Supabase.

Implement OTP using the existing backend.

Use:

* Nodemailer for sending email OTP
* Existing database for storing OTP records
* Existing authentication/JWT system
* Existing user table

OTP Requirements:

* Email OTP verification during signup.
* OTP verification for login 2FA.
* OTP verification for forgot password.
* Resend OTP button with cooldown timer.
* OTP expiry time: 5 minutes.
* Maximum OTP verification attempts: 5.
* Maximum OTP requests: 3 per 5 minutes per user.
* Maximum OTP requests: 10 per hour per user.
* Store OTP in hashed form, not plain text.
* Delete/invalidate OTP after successful verification.
* Prevent brute-force OTP attempts.
* Show clear OTP success/error messages.
* Keep email credentials only in backend environment variables.
* Do not expose email credentials in frontend.
* Make OTP pages responsive.

Use Gmail SMTP + Nodemailer for now.
Later, allow migration to Resend, Brevo, SendGrid, or Twilio Verify if needed.
