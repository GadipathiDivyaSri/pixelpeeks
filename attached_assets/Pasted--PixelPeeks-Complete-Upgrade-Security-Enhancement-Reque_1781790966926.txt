# 2. Email OTP Verification During Signup

After signup:

1. User enters:

   * Name
   * Email
   * Password

2. User account is created as:

   * Pending
   * Unverified

3. Generate secure OTP.

4. Send OTP to email using Nodemailer.

5. User enters OTP.

6. Account becomes verified.

7. User can login.

Important:

OTP MUST ONLY BE SENT TO EMAIL.

OTP MUST NEVER APPEAR:

* On website
* In frontend UI
* Browser console
* API responses
* Network tab
* Logs
* Toast messages
* Alerts

Only show:

* OTP input field
* OTP sent message
* Resend OTP button

Requirements:

* OTP expires in 5 minutes.
* OTP stored hashed.
* Limit OTP attempts.
* Resend OTP cooldown.
* One-time usage only.

# 5. Multi-Encryption Architecture

IMPORTANT:

Previously PixelPeeks only supported AES encryption.

Frontend currently behaves as if AES is the only encryption method.

Now multiple encryption methods have been added and ALL must be integrated into the frontend and backend workflow.

Supported Methods:

1. AES-256-GCM (Recommended Default)
2. AES-256-CBC
3. ChaCha20-Poly1305
4. Triple DES (Legacy)

Frontend Requirements:

* Add encryption selector.

* Display selected method.

* Show encryption method in:

  * Encode results
  * Decode results
  * File metadata
  * History logs
  * Dashboard

* Mark:

  * AES-256-GCM as Recommended
  * Triple DES as Legacy

* Remove AES-only UI assumptions.

# 6. EXACT ENCRYPTION WORKFLOW

When Encoding:

Step 1:
User uploads image.

Step 2:
User enters secret message.

Step 3:
User selects encryption method.

Step 4:
User enters encryption password.

Step 5:
Password must NEVER be used directly.

Generate:

* Salt
* IV/Nonce

Use:

* Argon2 (preferred)
  OR
* PBKDF2

to derive encryption key.

Step 6:
Encrypt message using selected encryption algorithm.

Step 7:
Store encryption metadata:

* Encryption Method
* Salt
* IV/Nonce
* Authentication Tag (if required)

Step 8:
Embed encrypted ciphertext into image.

Step 9:
Generate encoded image.

Result:
Original secret message must never be stored inside image directly.
Only encrypted ciphertext should be embedded.

---

# 7. EXACT DECRYPTION WORKFLOW

When Decoding:

Step 1:
User uploads encoded image.

Step 2:
Extract metadata.

Step 3:
Detect encryption method automatically.

Step 4:
Request password.

Step 5:
Use stored:

* Salt
* IV
* Metadata

Step 6:
Derive key again.

Step 7:
Decrypt ciphertext.

Step 8:
Display original message.

Requirements:

If password incorrect:

* Show proper error.

If metadata missing:

* Show warning.

If unsupported encryption:

* Show warning.

If file corrupted:

* Show warning.

Never crash application.
